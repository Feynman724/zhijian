# 织见：团队讨论空间与讨论产出 Demo

这版 Demo 聚焦两项核心能力：

1. 把群聊、线上语音会议和线下讨论放进同一个讨论空间，让团队直接在产品里完成讨论，而不是会后再收集信息。
2. 根据讨论类型生成真正会被使用的产出：决策会保留结论，分工会列出负责人和期限，辩论会保留双方观点与依据。

AI 是贯穿两项能力的接入原则。它通过群聊里的 `@织见机器人` 参与，不提供单独的 AI 聊天框；用户可以配置兼容 API，也可以把完整上下文导出为 Markdown 或 JSON，交给任意模型继续分析。

## 运行

在当前目录执行：

```bash
npm run serve
```

然后访问 `http://localhost:4173`。

## 推荐演示流程

1. 在“讨论空间”点击“开始语音讨论”，查看线上语音如何与群聊和线下记录进入同一场讨论。
2. 浏览 09:15 的语音讨论卡，回放会议并查看自动转写。
3. 查看张轩灏在 09:37 发送的 `@织见机器人`，以及机器人如何引用跨来源内容生成产出。
4. 在右侧切换“结论”“行动项”“分歧”，检查负责人、期限、双方观点和原始依据。
5. 点击左侧“讨论产出”，集中查看本场讨论生成的三类结果。
6. 在输入框中 `@织见机器人` 询问“请整理当前决策”或“请导出上下文”，观察机器人直接在群聊中回答。
7. 点击“模型接入”，查看 OpenAI 兼容、Anthropic 兼容、自定义接口和仅导出模式。
8. 点击“导出上下文”，切换 Markdown/JSON，检查导出内容中的时间、成员、来源、引用关系和结构化产出。

## 实现边界

- 当前版本是静态交互 Demo，预置内容用于完整演示产品流程。
- 模型配置界面不会发送远程请求，也不会保存输入的密钥；它用来演示供应商可替换的产品边界。
- Markdown/JSON 导出由浏览器本地生成，可复制或下载。
- 上传的图片和文本文件只在当前页面会话中预览；录音保存在当前会话，不做远程语音识别。
- 刷新页面会恢复到预置讨论。
